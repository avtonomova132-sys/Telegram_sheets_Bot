# Maitreya — бот-помощник Elena

Telegram-бот на Node.js, разворачивается на Railway. Личный ассистент Elena
(Бали) по трём направлениям: волонтёрская координация хостов Zoom-трансляций
для русскоязычной дхарма-общины (WVP / Geshe Michael Roach), контроль
прямых передач "Пять домов" перед курсами, и личные практики/задачи.

Elena — нетехнический пользователь, работает с телефона. Код пишется через
Claude Code (эта среда) и мержится в ветку `uttaratantra-verse` → Railway
автодеплой. В обычном чате с Claude (claude.ai, не Code) нет прав на пуш в
этот репозиторий — оттуда фичи приходят уже готовым кодом на ревью/перенос
сюда.

## Стек и деплой

- Node.js (`>=18`), `node-telegram-bot-api` (polling, не webhook), Express
  (отдаёт `/public` и JSON API для afisha.html)
- `@anthropic-ai/sdk` — разбор свободного текста/голоса (NLP-парсинг задач,
  дневника и т.д.), модель `claude-sonnet-4-6`
- `openai` — только Whisper (`audio.transcriptions`) для распознавания
  голосовых сообщений, к остальному функционалу отношения не имеет
- `node-cron` — все периодические проверки идут через `cron.schedule`
- Railway Volume, примонтированный на `/data` — единственное персистентное
  хранилище (обычный диск сервиса эфемерный, обнуляется при передеплое).
  Все `*.json`-хранилища живут там, путь у каждого переопределяется своей
  env-переменной (см. таблицу ниже) — по умолчанию `/data/<имя>.json`
- Ветка `main` — базовая/старая, реальная разработка идёт в
  `uttaratantra-verse` (Railway задеплоен именно с неё)

## Ключевые архитектурные решения (сквозные, применены во всех модулях)

- **Атомарная запись**: везде `tmp`-файл + `fs.renameSync` вместо прямой
  перезаписи — обрыв процесса на середине записи не должен портить JSON
- **"Сегодня" по Бали** — фиксированный сдвиг UTC+8 (Asia/Makassar, без DST),
  а не таймзона контейнера. Каноническая реализация — `baliDateString`/
  `baliHour` в `verse/progress.js`, переиспользуется остальными модулями,
  где нужна дата/час по Бали
- **Catch-up вместо точного выстрела cron'ом**: разовые события (ежедневное
  изречение, дневник) шлются через poll каждые 5 минут ("уже наступило ли
  время X и отправляли ли мы уже сегодня"), а не через cron на конкретную
  минуту — единичный пропущенный тик (рестарт контейнера) не значит пропуск
  всего дня, следующая проверка сама досылает
- **Session-guard для свободного текста**: в `bot.on('message', ...)`
  свободный текст проходит цепочку проверок сверху вниз (уточнение
  /габариты → сессия /new → неотвеченная запись дневника → /задача-паттерн
  → парсер напоминаний → эхо-заглушка) — каждая функция возвращает
  true/false, останавливая цепочку, если перехватила сообщение
- **`msg.chat.type !== 'private'` гвард** в начале `bot.on('message')` —
  personal-фичи (напоминания, /new, /задача, дневник) не должны реагировать
  на сообщения в группах
- **Доверенные пользователи** (`auth.js`, `isTrustedUser`) — owner-only
  команды (`/добавить`, `/дубли`, `/разделить`, `/группы`,
  `/обновитьссылки`) доступны только `MY_CHAT_ID` и id из
  `TRUSTED_USER_IDS`; пустой список = отказ всем, не допуск всем

### Шестиразовый дневник (`dnevnik/`) — самая активно дорабатываемая фича

Буддийская практика осознанности (традиция ACI / Geshe Michael Roach,
источник принципов — официальный "Gold Клуб",
facebook.com/groups/goldclubACIP). 6 раз в день по Бали (сейчас 8:00,
10:30, 13:00, 15:30, 18:00, 20:30 — SLOTS в `dnevnik/schedule.js`, менялось
уже дважды, там же живёт единственное место с хардкодом времени) бот
присылает один из 10 принципов (три тела, четыре речи, три ума,
`dnevnik/principles.js`), по кругу без остановки. Каждый принцип хранит
`negative`/`positive` (короткая формулировка), ПОЛНЫЙ список
`negativeExamples`/`positiveExamples` (15+ пунктов у некоторых принципов,
дословно из Gold Клуб — не обрезать, не пересочинять) и кураторские
`previewNegative`/`previewPositive` (сейчас НЕ используются — Elena
попробовала короткую версию и попросила вернуть полную даже в компактных
местах, см. `dnevnik/view.js: previewNegative/previewPositive` — сейчас
это просто алиасы на полные списки, оставлены на случай отката).

**Модель данных (важно, менялась):** одна запись (`dnevnik/store.js`) —
это один слот дня, с массивами `pluses[]`/`minuses[]` (НЕ единичный
`type`+поля — так было раньше, но Elena часто описывает НЕСКОЛЬКО
отдельных ситуаций под одним принципом, и это не должно схлопываться в
одну). Каждый элемент `pluses`: `{ text, radost, posvyashenie }`. Каждый
`minuses`: `{ opora, sozhalenie, antidot, reshenie }` (четыре противосилы
ACI — Опора/Сожаление/Антидот/Решение). `view.js: buildPrincipleResult`
поддерживает и старый плоский формат (записи, отвеченные до перехода на
массивы) через фолбэк — не удалять эту совместимость, старые записи в
`/data/dnevnik.json` реальных пользователей всё ещё в старом формате.

**Три способа ответить, разный приоритет** (`handleDnevnikPendingText` в
index.js):
1. **Кнопка** (`dnevnikSelectedEntryId`, в памяти, не на диске) — нажата
   явно в `/дневник_день` или в вечернем списке, самый надёжный способ,
   без ограничения по времени
2. **Живой слот** — окно `PENDING_WINDOW_MINUTES` (149 минут = почти до
   следующего слота, было 30 — Elena попросила увеличить, в чате бота
   параллельно падают другие уведомления, не всегда успевает быстро)
3. **Вечерний пакетный разбор** — свободный текст без выбора, если сегодня
   есть пропущенные (`getMissedToday`) — распознаёт номер принципа по
   смыслу/явному упоминанию, без гарантии

Во всех трёх случаях модели передаётся список **всех** сейчас открытых
принципов разом (`parseDnevnikBatch` в `dnevnik/parse.js`), не один — Elena
часто рассказывает несколько историй в одном сообщении, даже про разные
принципы. Если есть "гарантированный" принцип (кнопка/живой слот) —
`parseSinglePrincipleFallback` подстраховывает, если модель его не заметила.

**Промпт для минусов (`MOMENT_INSTRUCTIONS` в parse.js) — калибровался по
живым сравнениям с отдельным "Дхарма ИИ"-ассистентом Elena** (она
параллельно гоняет те же тексты через ассистента, обученного на текстах
ACI, и присылает расхождения). Ключевые уточнения, УЖЕ внедрённые, не
переоткрывать заново:
- **Сожаление** — всегда РЕТРОСПЕКТИВНОЕ по логике причины-следствия,
  одинаково для собственного действия сейчас и для того, что произошло с
  ней: не "я делаю плохое", а "почему это всходит именно сейчас — потому
  что в прошлом было посеяно подобное". Без привязки к конкретному
  воспоминанию — обобщённая формулировка нормальна (если есть плод, значит
  было семя). Это сожаление (динамичная решимость), не вина (статичное
  чувство) — метафора яда/противоядия
- **Антидот** — само-сорадование как отдельный сильный вариант для
  самокритики после доброго поступка; плюс чтение/медитация/передача
  учений/дебаты/волонтёрство
- **Решение** — короткий срок (минуты/часы), не дни/недели
- Ловить СТАРЫЕ привычки, упомянутые мимоходом внутри хорошей истории
  ("раньше я X, а сегодня нет") — отдельный minus-элемент, даже если
  сегодняшний эпизод сам по себе плюс
- **ВСЕГДА от первого лица** ("я радуюсь", не "Elena радуется")

Для плюсов — обязателен отдельный шаг `radost` (прожитая радость,
отдельно от text) ПЕРЕД посвящением — "поливаем радостью, посвящаем,
радуемся".

**Отображение (`dnevnik/view.js`):** заголовок принципа без суффикса
"— плюс/минус" (тире путалось с минусом) — только ведущий символ.
Символы ➕/➖ со словом рядом (не ✅/❌ — те визуально совпадают с чек-боксами
"выполнено/не выполнено" в других частях бота, путало). У каждого принципа
**всегда обе секции** — если плюсов или минусов нет, явно "Плюс: не
наблюдался" / "Минус: не наблюдался", а не тишина. `safe()` хелпер не даёт
полю прорваться в текст как буквальный `undefined`.

**Критично, было причиной реального падения бота:** Telegram отклоняет
сообщения длиннее 4096 символов, а необработанная ошибка в async-хендлере
роняла весь процесс (unhandled promise rejection), не просто не отвечая.
После перехода на полные списки Gold Клуб это стало реальностью на
`/дневник_день` с несколькими принципами. **Все** отправки текста дневника
идут через `sendDnevnikMessage()` в index.js (режет через `chunkMessage` из
`report.js`, кнопки — на последний кусок) — если добавляешь новое место,
откуда дневник шлёт текст, использовать эту функцию, не `bot.sendMessage`
напрямую.

**Команды:**
- `/дневник_принцип [N]` — тестовая живая запись (реальное окно
  `PENDING_WINDOW_MINUTES`, но НЕ двигает ротацию — `slotIndex` вида
  `test-<timestamp>`, исключается из `/дневник` и `/дневник_день` через
  `isTestSlot`). Без номера — следующий по ротации
- `/дневник` — последние 10 записей, кратко
- `/дневник_день` — полный отчёт за сегодня, с кнопками под неотвеченными;
  формат специально рассчитан на копирование и пересылку кармическому
  партнёру/партнёру по щедрости

**В 21:45 по Бали** (`EVENING_SUMMARY` в schedule.js) — если сегодня есть
пропущенные, автоматически присылает список с кнопками (`buildMissedListMessage`
+ `buildUnansweredKeyboard`), максимум раз в день (`getEveningSummaryDate`/
`setEveningSummaryDate` в progress-файле). Elena подчёркивала: НЕ подвязывать
напоминание к каждому ответу ("ещё ждёт ответа: N") — специально убрано,
пропущенное всплывает только в вечернем списке, без "довеска" после
каждого сообщения.

**Хранилище:** `/data/dnevnik.json` (записи, id = `dateBali#slotIndex`) +
`/data/dnevnik_progress.json` (счётчик ротации `lastPrincipleSent` +
`eveningSummaryDate`, оба сеттера мержат поверх текущего состояния — не
затирать один сеттером другого поля).

**Статус:** активно используется Elena ежедневно, дорабатывается почти
каждый день по живой обратной связи. Следующий возможный шаг (обсуждался,
не начат): отдельный бот для её "партнёра по щедрости" — тот же код,
отдельный `BOT_TOKEN`/`MY_CHAT_ID`/volume, никакого пересечения данных.

## Переменные окружения (Railway)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота (обязательна) |
| `MY_CHAT_ID` | личный chat_id Elena — получатель авто-рассылок (изречение, дневник, напоминания о передачах) |
| `TRUSTED_USER_IDS` | доп. доверенные пользователи через запятую, помимо `MY_CHAT_ID` |
| `WATCHED_GROUP_IDS` | группы, которые бот мониторит на анонсы передач |
| `BROADCAST_GROUP_IDS` | группы, куда дублируются напоминания о передачах |
| `ANTHROPIC_API_KEY` | все NLP-разборы (задачи, события, дневник, /габариты-vision) |
| `OPENAI_API_KEY` | только распознавание голоса (Whisper) |
| `WEEKLY_ANNOUNCE_HOUR` | час (Бали) воскресной авто-отправки `/weekly`, по умолчанию 10 |
| `VERSE_SEED_LAST_SENT` / `VERSE_FORCE_LAST_SENT` | первичный посев / ручная коррекция прогресса изречений |
| `*_PATH` (`VERSE_PROGRESS_PATH`, `PROEKTY_PATH`, `ZADACHI_PATH`, `PEREDACHI_PATH`, `EVENTS_PATH`, `ARTICLES_PATH`, `GROUP_LINKS_PATH`, `HOST_DIFF_STATE_PATH`, `WEEKLY_ANNOUNCE_STATE_PATH`, `DNEVNIK_PATH`, `DNEVNIK_PROGRESS_PATH`) | переопределение путей на volume, по умолчанию `/data/<имя>.json` — трогать не нужно, если не тестируешь локально |
| `PORT` | порт Express (Railway задаёт сам) |

## На что обратить внимание при доработках

- Elena формулирует задачи голосом через диктовку на телефоне — коряво,
  разговорно, со сбитыми знаками препинания. Anthropic-парсеры везде
  написаны с расчётом именно на такой ввод (см. системные промпты в
  `zadachi/items-parser.js`, `dnevnik/parse.js`) — при добавлении новых
  NLP-фич стоит держать эту же терпимость к неформальному тексту
- Новую персистентную фичу — по аналогии с существующими модулями: свой
  файл на `/data`, атомарная запись, `*_PATH` env-переопределение,
  `baliDateString`/`baliHour` для дат
- Периодическую отправку — по паттерну catch-up (poll раз в 5 мин), не
  точным cron на минуту
