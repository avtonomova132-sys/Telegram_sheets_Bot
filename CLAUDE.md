# Maitreya — бот-помощник Elena

Telegram-бот на Node.js, разворачивается на Railway. Личный ассистент Elena
(Бали) по трём направлениям: волонтёрская координация хостов Zoom-трансляций
для русскоязычной дхарма-общины (WVP / Geshe Michael Roach), контроль
прямых передач "Пять домов" перед курсами, и личные практики/задачи.

Elena — нетехнический пользователь, работает с телефона. Код пишется через
Claude Code (эта среда) и мержится в ветку `uttaratantra-verse` → Railway
автодеплой. В обычном чате с Claude (claude.ai, не Code) нет прав на пуш в
этот репозиторий — оттуда фичи приходят уже готовым кодом на ревью/перенос
сюда.

## Стек и деплой

- Node.js (`>=18`), `node-telegram-bot-api` (polling, не webhook), Express
  (отдаёт `/public` и JSON API для afisha.html)
- `@anthropic-ai/sdk` — разбор свободного текста/голоса (NLP-парсинг задач,
  дневника и т.д.), модель `claude-sonnet-4-6`
- `openai` — только Whisper (`audio.transcriptions`) для распознавания
  голосовых сообщений, к остальному функционалу отношения не имеет
- `node-cron` — все периодические проверки идут через `cron.schedule`
- Railway Volume, примонтированный на `/data` — единственное персистентное
  хранилище (обычный диск сервиса эфемерный, обнуляется при передеплое).
  Все `*.json`-хранилища живут там, путь у каждого переопределяется своей
  env-переменной (см. таблицу ниже) — по умолчанию `/data/<имя>.json`
- Ветка `main` — базовая/старая, реальная разработка идёт в
  `uttaratantra-verse` (Railway задеплоен именно с неё)

## Ключевые архитектурные решения (сквозные, применены во всех модулях)

- **Атомарная запись**: везде `tmp`-файл + `fs.renameSync` вместо прямой
  перезаписи — обрыв процесса на середине записи не должен портить JSON
- **"Сегодня" по Бали** — фиксированный сдвиг UTC+8 (Asia/Makassar, без DST),
  а не таймзона контейнера. Каноническая реализация — `baliDateString`/
  `baliHour` в `verse/progress.js`, переиспользуется остальными модулями,
  где нужна дата/час по Бали
- **Catch-up вместо точного выстрела cron'ом**: разовые события (ежедневное
  изречение, дневник) шлются через poll каждые 5 минут ("уже наступило ли
  время X и отправляли ли мы уже сегодня"), а не через cron на конкретную
  минуту — единичный пропущенный тик (рестарт контейнера) не значит пропуск
  всего дня, следующая проверка сама досылает
- **Session-guard для свободного текста**: в `bot.on('message', ...)`
  свободный текст проходит цепочку проверок сверху вниз (уточнение
  /габариты → сессия /new → неотвеченная запись дневника → /задача-паттерн
  → парсер напоминаний → эхо-заглушка) — каждая функция возвращает
  true/false, останавливая цепочку, если перехватила сообщение
- **`msg.chat.type !== 'private'` гвард** в начале `bot.on('message')` —
  personal-фичи (напоминания, /new, /задача, дневник) не должны реагировать
  на сообщения в группах
- **Доверенные пользователи** (`auth.js`, `isTrustedUser`) — owner-only
  команды (`/добавить`, `/дубли`, `/разделить`, `/группы`,
  `/обновитьссылки`) доступны только `MY_CHAT_ID` и id из
  `TRUSTED_USER_IDS`; пустой список = отказ всем, не допуск всем

### Шестиразовый дневник (`dnevnik/`) — самая активно дорабатываемая фича

Буддийская практика осознанности (традиция ACI / Geshe Michael Roach,
источник принципов — официальный "Gold Клуб",
facebook.com/groups/goldclubACIP). 6 раз в день по Бали (сейчас 8:00,
10:30, 13:00, 15:30, 18:00, 20:30 — SLOTS в `dnevnik/schedule.js`, менялось
уже дважды, там же живёт единственное место с хардкодом времени) бот
присылает один из 10 принципов (три тела, четыре речи, три ума,
`dnevnik/principles.js`), по кругу без остановки. Каждый принцип хранит
`negative`/`positive` (короткая формулировка), ПОЛНЫЙ список
`negativeExamples`/`positiveExamples` (15+ пунктов у некоторых принципов,
дословно из Gold Клуб — не обрезать, не пересочинять) и кураторские
`previewNegative`/`previewPositive` (сейчас НЕ используются — Elena
попробовала короткую версию и попросила вернуть полную даже в компактных
местах, см. `dnevnik/view.js: previewNegative/previewPositive` — сейчас
это просто алиасы на полные списки, оставлены на случай отката).

**Модель данных (важно, менялась):** одна запись (`dnevnik/store.js`) —
это один слот дня, с массивами `pluses[]`/`minuses[]` (НЕ единичный
`type`+поля — так было раньше, но Elena часто описывает НЕСКОЛЬКО
отдельных ситуаций под одним принципом, и это не должно схлопываться в
одну). Каждый элемент `pluses`: `{ text, radost, posvyashenie }`. Каждый
`minuses`: `{ opora, sozhalenie, antidot, reshenie }` (четыре противосилы
ACI — Опора/Сожаление/Антидот/Решение). `view.js: buildPrincipleResult`
поддерживает и старый плоский формат (записи, отвеченные до перехода на
массивы) через фолбэк — не удалять эту совместимость, старые записи в
`/data/dnevnik.json` реальных пользователей всё ещё в старом формате.

**Три способа ответить, разный приоритет** (`handleDnevnikPendingText` в
index.js):
1. **Кнопка** (`dnevnikSelectedEntryId`, в памяти, не на диске) — нажата
   явно в `/дневник_день` или в вечернем списке, самый надёжный способ,
   без ограничения по времени
2. **Живой слот** — окно `PENDING_WINDOW_MINUTES` (149 минут = почти до
   следующего слота, было 30 — Elena попросила увеличить, в чате бота
   параллельно падают другие уведомления, не всегда успевает быстро)
3. **Вечерний пакетный разбор** — свободный текст без выбора, если сегодня
   есть пропущенные (`getMissedToday`) — распознаёт номер принципа по
   смыслу/явному упоминанию, без гарантии

Во всех трёх случаях модели передаётся список **всех** сейчас открытых
принципов разом (`parseDnevnikBatch` в `dnevnik/parse.js`), не один — Elena
часто рассказывает несколько историй в одном сообщении, даже про разные
принципы. Если есть "гарантированный" принцип (кнопка/живой слот) —
`parseSinglePrincipleFallback` подстраховывает, если модель его не заметила.

**Промпт для минусов (`MOMENT_INSTRUCTIONS` в parse.js) — калибровался по
живым сравнениям с отдельным "Дхарма ИИ"-ассистентом Elena** (она
параллельно гоняет те же тексты через ассистента, обученного на текстах
ACI, и присылает расхождения). Ключевые уточнения, УЖЕ внедрённые, не
переоткрывать заново:
- **Сожаление** — всегда РЕТРОСПЕКТИВНОЕ по логике причины-следствия,
  одинаково для собственного действия сейчас и для того, что произошло с
  ней: не "я делаю плохое", а "почему это всходит именно сейчас — потому
  что в прошлом было посеяно подобное". Без привязки к конкретному
  воспоминанию — обобщённая формулировка нормальна (если есть плод, значит
  было семя). Это сожаление (динамичная решимость), не вина (статичное
  чувство) — метафора яда/противоядия
- **Антидот** — само-сорадование как отдельный сильный вариант для
  самокритики после доброго поступка; плюс чтение/медитация/передача
  учений/дебаты/волонтёрство
- **Решение** — короткий срок (минуты/часы), не дни/недели
- Ловить СТАРЫЕ привычки, упомянутые мимоходом внутри хорошей истории
  ("раньше я X, а сегодня нет") — отдельный minus-элемент, даже если
  сегодняшний эпизод сам по себе плюс
- **ВСЕГДА от первого лица** ("я радуюсь", не "Elena радуется")

Для плюсов — обязателен отдельный шаг `radost` (прожитая радость,
отдельно от text) ПЕРЕД посвящением — "поливаем радостью, посвящаем,
радуемся".

**Отображение (`dnevnik/view.js`):** заголовок принципа без суффикса
"— плюс/минус" (тире путалось с минусом) — только ведущий символ.
Символы ➕/➖ со словом рядом (не ✅/❌ — те визуально совпадают с чек-боксами
"выполнено/не выполнено" в других частях бота, путало). У каждого принципа
**всегда обе секции** — если плюсов или минусов нет, явно "Плюс: не
наблюдался" / "Минус: не наблюдался", а не тишина. `safe()` хелпер не даёт
полю прорваться в текст как буквальный `undefined`.

**Критично, было причиной реального падения бота:** Telegram отклоняет
сообщения длиннее 4096 символов, а необработанная ошибка в async-хендлере
роняла весь процесс (unhandled promise rejection), не просто не отвечая.
После перехода на полные списки Gold Клуб это стало реальностью на
`/дневник_день` с несколькими принципами. **Все** отправки текста дневника
идут через `sendDnevnikMessage()` в index.js (режет через `chunkMessage` из
`report.js`, кнопки — на последний кусок) — если добавляешь новое место,
откуда дневник шлёт текст, использовать эту функцию, не `bot.sendMessage`
напрямую.

**Команды:**
- `/дневник_принцип [N]` — тестовая живая запись (реальное окно
  `PENDING_WINDOW_MINUTES`, но НЕ двигает ротацию — `slotIndex` вида
  `test-<timestamp>`, исключается из `/дневник` и `/дневник_день` через
  `isTestSlot`). Без номера — следующий по ротации
- `/дневник` — последние 10 записей, кратко
- `/дневник_день` — полный отчёт за сегодня, с кнопками под неотвеченными;
  формат специально рассчитан на копирование и пересылку кармическому
  партнёру/партнёру по щедрости

**В 21:45 по Бали** (`EVENING_SUMMARY` в schedule.js) — если сегодня есть
пропущенные, автоматически присылает список с кнопками (`buildMissedListMessage`
+ `buildUnansweredKeyboard`), максимум раз в день (`getEveningSummaryDate`/
`setEveningSummaryDate` в progress-файле). Elena подчёркивала: НЕ подвязывать
напоминание к каждому ответу ("ещё ждёт ответа: N") — специально убрано,
пропущенное всплывает только в вечернем списке, без "довеска" после
каждого сообщения.

**Хранилище:** `/data/dnevnik.json` (записи, id = `dateBali#slotIndex`) +
`/data/dnevnik_progress.json` (счётчик ротации `lastPrincipleSent` +
`eveningSummaryDate`, оба сеттера мержат поверх текущего состояния — не
затирать один сеттером другого поля).

**Статус:** активно используется Elena ежедневно, дорабатывается почти
каждый день по живой обратной связи. Следующий возможный шаг (обсуждался,
не начат): отдельный бот для её "партнёра по щедрости" — тот же код,
отдельный `BOT_TOKEN`/`MY_CHAT_ID`/volume, никакого пересечения данных.

## На что обратить внимание при доработках

- **Дата эфира WVP — ТОЛЬКО из колонки Data** (правило Елены, 2026-10-12;
  `report.js: parseTabEvents` / `parseDataCellDate`). Дата «(Mon DD, YYYY)» в
  названии для расчёта НЕ используется (названия устаревают — ACI 18 стоял в
  названии 18 окт, а по таблице 25 окт). Если года в ячейке нет («Thu, 24
  September») выводится по дню недели. Расхождение с датой в названии, нечитаемая
  дата, странное время кладутся в `event.doubts`; карточка с `doubts` не даёт
  отправить Анонс в группу — вместо этого Елене в личку уходит весь Анонс с
  пометкой «Нужна проверка» (`cardButtons.js: sendWeekCards`, `reviewChatId`).
  Эфиры, у которых только название указывает на неделю, а Data — на другую
  (`collectWeekEvents().strays`), в Анонс не входят, Елене уходит справка.
  `assistance.js` и `assistantsSeries.js` пока читают дату по-старому (название
  первым) — отдельные фичи, не менялись.
- **Пометка «off» = эфира не будет** (правило Елены, 2026-10-13;
  `report.js: rowMarkedOff`). Если в ЛЮБОЙ текстовой ячейке строки эфира есть
  слово «off» (любой регистр, целым словом: «off», «OFF», «DAY OFF», «day-off»),
  строка не считается эфиром — не попадает ни в Анонс, ни в счётчик, ни в
  `/check`, ни в проверку хостов. Цвет ячеек не используется, ссылки игнорируются.
  Пропущенные строки лежат в `events.offEvents` / `collectWeekEvents().skippedOff`
  (Елене показываются в «Списке проверки»).
- **Схема недели WVP и «закрыт эфир»** (правила Елены, 2026-10-15;
  `cardButtons.js`). Хостов ровно 8 в начале (теперь список — в хранилище, см. ниже; @lp129eric1 и
  @svet75afan не хосты и в тегах не нужны). Эфир ЗАКРЫТ, если в таблице в колонке
  Host есть любое имя (даже не из списка хостов) ИЛИ в группе есть активная бронь
  ✅ (не снятая Undo); СВОБОДЕН — только без того и другого. `/check` (в личке)
  использует то же правило: бронь без имени в таблице показывается строкой
  «🔒 Зарезервировал(а) @…, ещё не вписан(а) в таблицу» и не считается эфиром без
  хоста (хук `setReservationLookup` в report.js; без свободных — «✅ Все эфиры
  недели закрыты»). Воскресенье 10:00 — Анонс (авто-отправка на ПАУЗЕ); +24 ч —
  напоминание в группе (`checkAndSendAnnounceReminders`); +48 ч (вторник 10:00) —
  ТОЛЬКО если остались свободные эфиры, одно сообщение Елене в личку (кого
  писать / не писать + готовый текст без кнопок; `runTuesdayCheck`). Бот сам
  хостам НИЧЕГО не пишет. Как только все эфиры Анонса закрыты — один раз
  «🎉 Ура!» Елене и «✅ All sessions are covered…» в группу ответом на шапку,
  напоминания недели отменяются; Undo → «🔓 Эфир снова свободен», схема
  возвращается (`evaluateCoverage`). Состояние — поля `coveredAt`,
  `cancelledByCover`, `tuesdayDoneAt` у батча в `/data/card_buttons.json`.
- **Недельная автоматика С ПОДТВЕРЖДЕНИЕМ Елены, без ИИ** (2026-10-21;
  `cardButtons.js`: `weekSchedulerTick`, раз в 5 мин + один раз через 45 с после
  старта; ЗАМЕНЯЕТ расписание из предыдущего пункта). Время по Бали. В группу сам
  бот пишет ТОЛЬКО «✅ All sessions are covered…» (когда всё закрыто); Анонс и
  напоминание уходят в группу лишь после «да» Елены. Воскресенье 09:00 — превью
  Анонса на следующую неделю Елене в личку (то же, что уйдёт в группу + кнопки
  «Отправить в группу / Не отправлять»); понедельник 09:00 — превью напоминания;
  вторник 09:00 — сообщение Елене (кому писать, текст без кнопок; хостам бот сам
  не пишет). «Да» = кнопка, ответ «да»/«нет» на вопрос превью, `/yes` / `/no`;
  перед отправкой таблица сверяется снова — если список эфиров изменился, уходит
  новое превью с «что поменялось» (`verify` в `sendWeekCards`). Нет ответа до
  12:00 — одно напоминание Елене. `/announce [next|this|ГГГГ-ММ-ДД]` — превью по
  запросу (слот воскресенья не расходует). Пропущенный слот: если бот вернулся не
  позже чем через 3 ч — выполняется один раз; позже — не выполняется, Елена
  получает сообщение. Любая ошибка (таблица, Telegram) → личка Елене
  (`reportProblem`, не чаще раза в час на ключ). Состояние — `store.scheduler`
  (`done`, `pending`, `errors`, `activatedAt`) в `/data/card_buttons.json`. Сверка
  карточек с таблицей — каждые 15 мин (`syncCardsWithSheet`, только живые Анонсы),
  поэтому «ура» срабатывает и когда хост вписался в таблицу без кнопки. Прямая
  воскресная авто-отправка в группу из index.js УДАЛЕНА (`WEEKLY_ANNOUNCE_ENABLED`
  больше ничего не значит). Исключение: `/next_week` в группе (только доверенный)
  по-прежнему шлёт сразу — это ручная команда.
- **Список хостов — в хранилище бота, не в коде** (Елена, 2026-10-21;
  `hostsStore.js`, `hostAdmin.js`). Файл `/data/hosts.json` (`HOSTS_PATH`) на
  постоянном томе Railway; при самом первом запуске создаётся из
  `host-candidates.json` (теперь это только стартовый набор — менять его
  бесполезно, правки идут командами). Для каждого хоста: @username, Telegram-ID
  (узнаётся, когда человек нажал кнопку под карточкой, написал боту или написал в
  группе), имя из профиля, «писал боту». Сопоставление по ID, если он известен
  (смена @username подхватывается сама), иначе по @username. Всё остальное
  (теги, «из N», кто может нажимать, «не отметились», `/check`-теги) берёт список
  отсюда; N считается сам. Команды (только Елене в личке): `/hosts`,
  `/host_add @имя`, `/host_remove @имя` (с `test` в конце — на тестовой копии
  `/data/hosts_test.json`). Бронь ✅ убранного хоста не снимается сама: Елене
  приходит список эфиров с кнопкой «Снять бронь». Наблюдение за группой:
  уход хоста → вопрос «Убрать?» [✅/❌], вступившие → ОДИН общий вопрос
  «Добавить?» [✅/❌]; события `chat_member` Telegram шлёт, только если бот —
  АДМИНИСТРАТОР группы (в `index.js` для этого заданы `allowed_updates`), плюс
  запасная проверка ухода раз в 30 минут по сохранённым ID (`getChatMember`).
  Тестовая группа «Дебаты» ведёт себя так же, но меняет только копию списка.
- **Вторничная сводка Елене** (2026-10-22; `cardButtons.js: buildTuesdayMessages`).
  Приходит ТОЛЬКО во вторник в 09:00 по Бали и только для Анонса, отправленного
  до этого момента (мид-недельный Анонс вторничной сводки не получает), и только
  если остались свободные эфиры (бронь = закрыт, броней и «уже ответивших» в
  сводке нет). Это 3–4 отдельных простых текстовых сообщения: (1) «Нужны N
  хоста», эфиры, «Кому написать» — по строке на человека с языком RU / EN /
  RU+EN (⚠️ если бот не знает его Telegram-ID); (2) готовый русский текст;
  (3) английский; (4) двуязычный для «RU+EN». Язык: `language_code` Telegram
  (ru, uk, be, kk… → RU, прочие → EN; хранится в `/data/hosts.json` как `lang`,
  запоминается при нажатии кнопки/сообщении), без него — кириллица в имени
  профиля → RU, иначе RU+EN (бот не гадает). Ссылка в тексте — на вкладку и на
  строку эфира (`event.row` → `…#gid=…&range=A<строка>`). `/tuesday` — то же
  самое по запросу в любой день.
- **Срочное напоминание «осталось меньше 24 часов»** (2026-10-22;
  `cardButtons.js: urgentStep`, раз в час в `weekSchedulerTick`, без ИИ).
  Свободный эфир (нет имени в Host и нет активной брони) начинается через ≤24 ч и
  ещё не обработан → если есть не отметившиеся (ни ✅, ни ❌ ни по одной карточке
  Анонсов этой недели) — Елене превью «как уйдёт в группу» (двуязычный текст с
  тегами ТОЛЬКО не отметившихся + карточка ✅/❌ только на этот эфир) и кнопки
  «Отправить / Не отправлять» (или да/нет, /yes /no); если не отметившихся нет —
  одно сообщение Елене «Все хосты ответили, но эфир … не закрыт», в группу
  ничего. Один раз на эфир (после «Не отправлять» больше не шлётся). С 22:00 до
  08:00 по Бали Елене не пишет — делает в 08:00. Закрылся до ответа → превью
  снимается («эфир уже закрыт»). Срочная карточка — отдельный batch (`kind:
  'urgent'`, без пн/вт-рассылок), но входит в НЕДЕЛЬНУЮ проверку «ура». «Ура» теперь
  считается по всей неделе (все живые Анонсы чата за Пн–Вс + срочные карточки) и
  только если последнее почасовое сканирование не знает свободного эфира без
  карточки (`scheduler.lastScan`); одно сообщение в группу ответом на шапку самого
  нового Анонса. `/urgent_test` — тот же текст сразу в «Дебаты».
- **Статусы хостов: «на уточнении» и «пауза»** (2026-10-26; `hostsStore.js`).
  Активный хост — тегается, считается в «из N», попадает в сводки. «На уточнении»
  (`status: 'hold'`; ждём ответа Елены «оставить / убрать» кнопками
  `hw:hold:keep|drop`) и хост «на паузе» (`pause: {from, until}`, мс; команда
  `/host_pause @имя [с ГГГГ-ММ-ДД] до ГГГГ-ММ-ДД`, возврат — `/host_resume`; обе
  даты в 09:00 по Бали, «до» — уже в обычном режиме) НЕ тегаются, НЕ считаются в
  «из N» и не попадают во вторничную/срочную логику (`hosts.tags()` = только
  активные), но их нажатия по-прежнему принимаются как нажатия хоста, а ❌ видны в
  блоке статуса (числитель = все нажавшие хосты, знаменатель = активные). В блоке
  статуса карточек имена — обычным текстом БЕЗ @ (и нажавшие, и «ещё не
  отметились»); @ — только в отдельном сообщении-напоминании, и только у тех, кто
  ни разу не нажал. `/hosts` показывает статус каждого. `rebuildReminderPreview` —
  отменить висящее превью напоминания и прислать новое по текущему составу.
  Разовое исключение (Елена, 2026-10-26): `record.countedExtras` на карточке —
  usernames, которые НЕ хосты (убрана Darya_Marchenko9), но их ❌ показан без @ и
  посчитан и в числителе, и в знаменателе «N из M» только на этой карточке
  (`addCountedExtraForEvent`); в теги, сводки и будущие напоминания они не
  попадают. @mih22 — обычный активный хост (статус «на уточнении» снят).
- **Напоминание об обучении «Хочу быть хостом»** (Елена, 2026-10-26; `training.js`,
  без ИИ, отдельно от Анонса/напоминания хостам/вторничной сводки/«за 24 часа»).
  Встреча каждый вторник 07:00 МСК = 12:00 Бали = пн 21:00 Аризона (время зашито в
  тексте, командой не меняется). Понедельник 14:00 по Бали (catch-up 3 ч, раз в 5 мин
  из того же cron, что `weekSchedulerTick`; метка недели `done[пн]` — второго превью
  и второй отправки за неделю не будет даже после рестарта) → Елене в личку превью с
  кнопками «Отправить в группу / Не отправлять» (`tr:ok|no:<id>`, «да»/«нет» ответом,
  `/yes` `/no` — берётся самое новое превью из недельных и этого) → после «да» текст
  (только по-русски, блоки через пустую строку, без кнопок и @-тегов) уходит в «WorldView Productions», тема General.
  Автомат: `/training_auto_on` — в понедельник 14:00 шлёт в группу сам, Елене одна
  строка «Напоминание об обучении отправлено в группу»; `/training_auto_off` — обратно;
  `/training_off` / `/training_on` — выключить/включить функцию. Ссылка на Zoom —
  `/training_link https://…` (в `/data/training.json`, `TRAINING_PATH`); задана — в тексте
  «🔗 Zoom: ссылка»; нет — «🔗 Ссылка на Zoom появится здесь завтра за 10 минут до
  начала, в 06:50 по Москве.» (кнопка «Отправить» и автомат работают и без ссылки;
  предупреждение «ссылка не задана» — только Елене над превью, в группу не идёт);
  после `/training_link` бот присылает новое превью. `/training_text` — готовый текст и режим, `/training_now` — превью сейчас,
  Время в тексте — только «Вт 07:00 по Москве» (Бали и Аризона убраны по просьбе Елены). `/training_test` — тот же текст в «Дебаты». Изменилась ссылка после превью → при «да»
  показывается обновлённый текст, не отправляется.
